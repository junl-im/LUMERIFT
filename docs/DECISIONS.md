# Architecture Decision Records

## ADR-001: 모바일 9:16 논리 해상도

- 결정: 540 × 960 논리 좌표를 사용하고 Pixi root를 화면에 맞춰 확대/축소한다.
- 이유: 아트 마스터 1080 × 1920과 정확히 2배 관계이며 저사양 기기 해상도 조절이 쉽다.

## ADR-002: Firebase 미설정 시 로컬 모드

- 결정: 환경 변수가 없으면 로컬 게스트와 LocalStorage Repository를 사용한다.
- 이유: 백엔드 설정이 전투와 UI 개발을 막지 않게 한다.

## ADR-003: Vite base는 상대 경로

- 결정: `base: './'`를 사용한다.
- 이유: GitHub Pages 프로젝트 경로와 사용자 페이지 모두에서 정적 경로 문제를 줄인다.

## ADR-004: SVG 완전 금지

- 결정: 에셋 검사 스크립트가 public과 src의 SVG를 실패 처리한다.
- 이유: 프로젝트의 고정 에셋 정책을 CI에서 강제한다.

## ADR-005: 런타임 Graphics는 기술 검증 전용

- 결정: Phase 1 테스트 씬은 Pixi Graphics를 사용하되 최종 게임 아트는 PNG/WebP Atlas로 교체한다.
- 이유: 아트 제작 전에 씬, 입력, 전투, 풀링, 성능 계층을 검증한다. Graphics는 SVG가 아니다.

## ADR-006: 실시간 MMO 기능 연기

- 결정: 파티, PvP, 길드전, 거래, 채팅은 MVP 이후다.
- 이유: 전투 손맛과 반복 성장 루프를 먼저 완성한다.

## ADR-007: 게임 작업명 LUMERIFT

- 결정: 영문 `LUMERIFT`, 한글 `루메리프트`, 부제 `균열의 계승자`를 MVP 공식 작업명으로 사용한다.
- 이유: 빛 에너지와 차원 균열이라는 세계관 핵심을 짧게 표현하며 한글 발음도 비교적 단순하다.
- 제한: 상용 출시 확정 전 전문 상표 조사, 앱스토어 이름, 도메인, 소셜 계정 가용성을 별도로 검토한다.

## ADR-008: 전투 판정과 렌더링 분리

- 결정: 플레이어와 몬스터의 상태·위치·공격 이벤트는 순수 TypeScript Controller가 관리하고 Pixi Scene은 표시와 입력 연결을 담당한다.
- 이유: 단위 테스트와 향후 Sprite Atlas 교체가 쉬워지고 렌더링 변경이 전투 규칙을 깨뜨리지 않는다.

## ADR-009: 전체 ZIP과 패치 ZIP 동시 제공

- 결정: 모든 버전은 전체 통합본과 직전 버전 대비 덮어쓰기 패치를 함께 배포한다.
- 이유: 신규 설치와 기존 작업본 업데이트를 모두 안전하게 지원하고 변경 파일을 추적하기 쉽다.


## ADR-010: 콘텐츠 수치 JSON 이전

- 결정: 플레이어, 액션, 몬스터, 스테이지 수치를 JSON으로 관리하고 `GameDataRegistry`가 시작 시 검증한다.
- 이유: 콘텐츠 추가가 화면 코드 변경으로 이어지지 않게 하고 잘못된 ID와 수치를 배포 전에 차단한다.

## ADR-011: 공격 Telegraph 의무화

- 결정: 정예와 보스의 범위 공격은 피해 전에 위험 범위를 표시한다.
- 이유: 모바일 화면에서도 회피 가능성을 보장하고 난도를 불공정한 즉사 패턴으로 만들지 않는다.

## ADR-012: 그래픽 품질과 게임 규칙 분리

- 결정: 품질 설정은 장식, 이펙트 밀도, 카메라 흔들림만 변경하고 피해·AI·판정은 변경하지 않는다.
- 이유: 저사양 사용자에게 동일한 게임 규칙과 경쟁 조건을 제공한다.

## ADR-013: 상태 이상 Controller 독립

- 결정: 화상과 둔화의 시간·틱·이동 배율은 `StatusEffectController`에서 관리한다.
- 이유: 몬스터 FSM과 상태 이상 규칙을 분리하고 향후 감전·중독·기절을 확장하기 쉽다.


## ADR-014: 소유 장비는 정의 ID와 UID를 분리

- 결정: 정적 장비는 `itemId`, 플레이어가 소유한 개별 장비는 `uid`로 구분한다.
- 이유: 같은 장비를 여러 개 보유하면서 강화·잠금 상태를 각각 저장할 수 있다.

## ADR-015: MVP 강화 실패 없음

- 결정: MVP 장비 강화는 골드만 소모하고 실패·파괴·단계 하락을 적용하지 않는다.
- 이유: 성장 루프 검증 단계에서 불필요한 좌절과 복잡한 확률 검증을 피한다.

## ADR-016: 저장 버전 명시와 자동 마이그레이션

- 결정: 플레이어 저장 데이터에 `saveVersion`을 두고 v1 데이터를 v2로 자동 변환한다.
- 이유: 기능 추가 시 기존 사용자의 저장 데이터를 깨뜨리지 않고 구조를 확장한다.

## ADR-017: 장비 수치는 실제 전투 Config에 합성

- 결정: 전투 진입 시 기본 캐릭터 데이터와 장착 장비 능력치를 합쳐 세션용 `PlayerCombatConfig`를 만든다.
- 이유: UI에만 전투력을 표시하는 가짜 성장 구조를 피하고 장비 선택이 실제 플레이에 영향을 주게 한다.

## v0.5 스테이지·퀘스트 결정

- MVP 첫 챕터는 10개 선형 스테이지로 고정한다.
- 최초 보상은 자동 지급하고 저장 플래그로 중복을 방지한다.
- 일일 퀘스트 초기화 기준은 서버 연동 전까지 UTC 날짜 키를 사용한다.
- 퀘스트 진행도는 개별 카운터를 중복 저장하지 않고 누적 통계와 스테이지 기록에서 계산한다.
- 최종 맵 아트 전까지 스테이지 구간별 팔레트로 분위기와 난이도 변화를 표현한다.

## ADR-006: 전투 에셋을 씬 번들로 관리

전투 전용 플레이어·몬스터·맵 리소스는 `battle-chapter-1` 번들로 묶는다. BattleScene 진입 시 로드하고 종료 시 참조를 해제한다. 초기 다운로드와 모바일 메모리 체류량을 줄이기 위한 결정이다.

## ADR-007: 8방향 Atlas 키 고정

MVP 플레이어 방향은 8방향으로 확정한다. 11방향은 제작량과 메모리 증가가 크므로 보류한다. 최종 아트 교체 시에도 `player.{state}.{direction}` 키를 유지한다.


## v0.7.0 결정 기록

- 모바일 이동은 별도 DOM이 아니라 Pixi Container 기반 가상 조이스틱으로 통일한다.
- 쿨다운은 SVG 없이 Pixi Graphics 원형 Arc로 표현한다.
- VFX는 런타임 Graphics만 늘리지 않고 WebP Atlas + AnimatedSprite + Object Pool을 기본으로 한다.
- 보스 페이즈 임계값은 MVP 기준 65%와 30%로 고정한다.
- 장착 장비 전체 외형 교체 전까지 장비 아이콘을 독립 레이어로 사용한다.
- 씬 전환 중 Fade Overlay가 입력을 차단하도록 한다.

## ADR-008: 인수인계 파일을 릴리스 필수 산출물로 고정

**결정:** 모든 릴리스에서 AGENTS, HANDOFF_MASTER, HANDOFF_LOG, HANDOFF_STATE를 갱신하고 자동 검증한다.

**이유:** 장기 누적 개발에서 메모리·규칙·진행 상태 유실을 방지하고 사람과 AI 간 작업 연속성을 보장하기 위해서다.

## ADR-009: v0.8을 온라인 기능보다 에셋 기반 확장에 우선 사용

**결정:** Firebase 운영 기능을 v0.9로 이동하고 v0.8에서 대규모 에셋 규격과 검수 기반을 먼저 확립한다.

**이유:** 전투·UI·도감·지역 확장을 반복할 수 있는 자산 계약이 먼저 필요하기 때문이다.
