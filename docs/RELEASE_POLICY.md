# Release Packaging Policy

모든 향후 버전은 다음 두 파일을 함께 제공한다. 필요할 때만 경량 런타임 패키지를 추가한다.

## 전체 통합 ZIP

- 현재 버전의 코드, 문서, 설정, 런타임 자산을 포함한다.
- `art_source`의 모바일 제작용 원본과 공개 라이선스 원본을 포함한다.
- 과거 제작 후보와 레거시 Atlas도 인수인계·재가공을 위해 포함한다.
- 라이선스, NOTICE, 생성·가공 도구를 포함한다.
- 새로 설치하거나 전체 교체할 때 사용한다.
- ZIP 내부 최상위 폴더명은 `lumerift`로 고정한다.
- 원본·보관 자산을 제외한 패키지는 전체 통합 ZIP이라고 부르지 않는다.

```text
LUMERIFT_FULL_v1.2.0.zip
└─ lumerift/
   ├─ art_source/
   ├─ public/assets/
   ├─ src/
   ├─ docs/
   └─ ...
```

## 선택적 경량 런타임 ZIP

- 서버 배포나 빠른 테스트용으로만 별도 제공할 수 있다.
- 이름에 `RUNTIME` 또는 `DEPLOY`를 사용한다.
- 전체 통합 ZIP을 대체하지 않는다.
- `art_source`와 기본 런타임에서 참조하지 않는 보관 자산을 제외할 수 있다.

## 덮어쓰기용 패치 ZIP

- 기준 배포 버전 이후 변경·추가된 파일을 포함한다.
- 기존 프로젝트 루트에서 압축을 풀어 덮어쓴다.
- ZIP에는 별도의 상위 폴더를 넣지 않는다.
- 삭제가 필요한 파일은 `PATCH_DELETE_LIST.txt`에 기록한다.
- 사용자가 중간 버전을 받지 않은 경우 마지막으로 전달된 버전부터 최신 버전까지 누적 패치를 제공한다.

## 용량 기준

- 사용자 보고는 십진 단위 MB를 사용한다.
- 초기 다운로드 15MB 제한은 최초 로드 번들 기준이다.
- 전체 통합 프로젝트와 전체 자산에는 15MB 제한을 적용하지 않는다.
- `art_source`는 `public` 밖에 두어 GitHub Pages 배포에 포함되지 않게 한다.

## 패치 검증

1. 기준 버전 복사본에 패치를 덮어쓴다.
2. `PATCH_DELETE_LIST.txt`의 파일을 제거한다.
3. 패치 메타 파일을 제외한다.
4. 패치 적용 결과와 전체 통합본을 파일 단위로 비교한다.
5. `npm run validate:archive`로 원본과 보관 자산이 유지되는지 확인한다.
6. 두 ZIP 모두 압축 무결성 검사를 통과해야 한다.

## 결과 보고 순서

1. 결과
2. 전체 통합 ZIP
3. 덮어쓰기용 패치 ZIP
4. 다음 업데이트 내용

## 모바일 제작용 원본 정책

FULL 패키지는 원본을 포함하되, 모바일 화면에서 품질 차이를 만들지 않는 과도한 해상도와 비압축 PNG는 `docs/SOURCE_ART_POLICY.md`에 따라 최적화한다. 경량화는 원본 삭제가 아니라 제작 규격 정상화로 기록한다.

## v1.6.0 public/보관소 분리

- FULL 패키지는 활성 런타임과 보관 자산을 모두 포함한다.
- GitHub Pages 배포는 `public`만 복사하므로 레거시·미사용 자산을 public에 보관하지 않는다.
- 패치에서 파일 이동이 필요한 경우 `RELOCATION_PLAN`과 Node 이동 스크립트를 제공한다.
- 패치 적용 완료 판정은 이동 후 전체본과 파일 해시가 일치해야 한다.


## v1.7.0 런타임 아트 교체 정책

- 새 실사용 경로를 등록한 뒤 이전 기본 경로 파일은 public에 중복 보관하지 않는다.
- 이전 자산은 `runtime_archive/<교체 버전>`에 이동하고 relocation plan에 해시를 기록한다.
- 패치 사용자는 덮어쓰기 후 `npm run asset:relocate`를 실행한다.
- 전체 통합본은 신규 실사용 자산과 이전 보관 자산을 모두 포함한다.
